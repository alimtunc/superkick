Patterns & states

The shared behaviours every surface inherits — so none of them get re-invented per screen: keyboard focus, the rail edit pickers, connection states, toasts, destructive confirms, and the full activity / history event vocabulary.

01

Focus & keyboard

Keyboard-first. Focus is a roving caret: the list uses a left accent bar + surface wash (no layout shift); controls show a :focus-visible ring. Mouse clicks never ring.

02

Rail edit pickers

Every mutable property (IssueUpdateRequest) opens the same popover pattern (tier 3, search + list, ⌥ to clear). Shown: assignee, label (multi), project, priority, estimate.

03

Connection / daemon states

Local-first: the UI talks to a local daemon. When it drops, a global bar pins under the topbar — inputs disable, live dots freeze, but cached data stays readable.

04

Toasts

Transient, bottom-right, z-toast. Auto-dismiss except when they carry an action (Undo / View).

05

Destructive confirm

Irreversible actions (cancel run, delete) use a compact confirm — the destructive verb is the primary, tinted danger.

Cancel run?

This stops run_a7c0e2 and discards the worktree. The issue stays in progress.

06

Activity & history vocabulary

Every IssueHistoryEvent kind rendered on the gutter connector, plus a threaded comment (parent_id / CommentNode.children). System events are inline; comments are tier-2 cards.
