System Legend

The single source of truth for the Superkick visual layer. Every token below is defined in tokens.css as a CSS custom property and consumed by every surface. Where the previous round left a value ambiguous, this page decides it once and shows it. North star: Linear — calm density, restrained color, glyph-led status.

Rule
If a color, tier, connector, or empty-state isn't made explicit here or on a surface page, it becomes an engineering guess. Everything that derailed the last round is pinned down on this page.
01

Elevation & color map

Superkick is flat and border-delineated, like Linear. Most chrome lives on the page floor (tier 0) and is separated by hairline borders — not by raising it. Elevation (lighter fill + shadow) is spent only on objects that genuinely float. This is the decision that was ambiguous last round: the issue-detail body floor is tier 0, and the properties rail sits on tier 0 too, separated by a border.

10

Real-data sparsity rule

The app's data is sparse: assignee, project, cycle, estimate, completed_at, linked run and description are all nullable. The omitted-field treatment is decided once, by context:

List row / card
Hidden — collapse the cell

No estimate → no estimate cell. No project → no project chip. No agent run → no state dot. Rows stay compact; absence reads as absence, never as a gap to interpret.

Properties rail / detail
Shown — dim actionable placeholder

Every property row is always present with a "Add estimate…" placeholder, so the operator can set it in place. Empty description → italic "No description" prompt.

11

Focus & keyboard

Keyboard-first. List focus is a roving caret — a left accent bar + surface wash, no layout shift; controls use a :focus-visible ring (mouse clicks never ring). Full spec + the shortcut table live on Patterns & states.
